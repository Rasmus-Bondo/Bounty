## Fixed

- **35 revolver sounds were reachable by no volume setting at all.** The HellFire skin's seven sounds
  (`FireSound`, `ReloadSound`, `TriggerSound`, `ReloadFinish`, `DashSound`, `DashSound2`,
  `DashReload`) carried no `SoundGroup` in **five** separate copies: `RevolverDefaultViewmodel` in
  each match place, and `Workspace.HellFireWire`, `WeaponSkins.Dust.HellFire` and
  `WeaponSkinsWorld.Dust.HellFire` in Bounty. There is no `SoundService.Volume` and "Master" is faked
  by multiplying into each group, so an ungrouped Sound escapes all four sliders. All 35 now carry
  `SFX`, which is what every other copy of the same assets already used.

  Set directly in each place rather than mirrored: `SoundGroup` is an instance reference, and `.rbxm`
  drops those at serialize time.

  **The count moved twice while fixing it, which is the useful part.** A first scan found seven, a
  second found Bounty's world gun, and only an *uncapped* re-scan found the remaining fourteen — the
  earlier passes printed at most ten hits per root and silently truncated. Audit output that caps its
  own listing cannot be read as a total.

  Verified by uncapped re-scan of every place: Redwater 108/108 grouped, Frostbite 99/99, Bounty
  41/51. The last ten are `ReplicatedStorage.LootboxSFX` in Bounty, left deliberately and filed as
  open item 112 — their only consumer is a disabled `LocalScript`.

- **The death cam you get with no killer can now be looked around, like the killer cam always
  could.** Dying to the zone/firewall, to a fall, or by resetting yourself left the camera pinned
  to one frozen CFrame for the whole respawn wait — no mouse orbit, no touch drag. `KillCamClient`'s
  `startFallbackDeathCam` now sets `isOrbiting` and calls `setupTouchInput`, and its `RenderStepped`
  loop runs `updateMouseOrbit` and rebuilds the CFrame each frame, so it shares the killer cam's
  yaw/pitch state, sensitivities, right-drag gate and pitch clamps. Redwater only — no shared
  modules, no server change.

  **Rollback risk is the extracted maths, not the cam.** `getOrbitCFrame(root)` is now a thin
  wrapper over a new `getOrbitCFrameAround(pivot, distance, riseHeight)`, so reverting the fallback
  alone leaves the killer cam calling a function that no longer exists — revert both or neither.
  The fallback orbits a **fixed** pivot at the corpse rather than a tracked part, deliberately: the
  body ragdolls and a self-reset destroys the character outright.

  Verified: script compiles, and the starting shot was checked numerically against the fixed CFrame
  it replaces — the framing is authored as the same `(0, 7, 13)` offset with its yaw/pitch solved
  back out, a full 360° yaw sweep holds the radius to 1e-5 studs, and the camera stays aimed at the
  pivot to within 0.03°. The shot sits 1.1 studs / 4.3° off the old one on purpose: `(0, 7, 13)`
  solves to -28.3°, which is `MIN_PITCH` exactly, so a 4° margin keeps the first drag live in both
  directions. **Confirmed in a manual playtest 2026-08-13** — the killer-less cam orbits.

- **Trading Post EQUIP/BUY NOW caption no longer renders at a fixed 14px on big screens.**
  `BuyHunterSkinFrame.PurchaseFrameTokens.PriceLabel` — the one action label the whole skin/weapon
  detail panel shares — was authored `TextScaled = false` while every sibling label (its own
  subtitle, both hunter buy buttons, the card price) is `TextScaled = true`, so the pill grew with
