## Fixed

- **Redwater matches are now reserved servers, and Roblox can no longer put anyone in one.**
  Four separate launch complaints were one root cause. Join gating has to be enforced at the
  *sending* end, in Bounty, because a Roblox server cannot refuse matchmaking — so when nothing
  was open the lobby left the destination blank and Roblox chose. That blank was a second
  entrance nobody controlled and which had never read the match directory, and at launch
  population "nothing is open" was the *common* case, not the edge case. With a 360-second round
  and a 180-second lock, a server was unroutable-by-us but fillable-by-Roblox for **53% of its
  life**. All four symptoms close on the same change:
  - Players dropped into a match that shut down ~10 seconds later, then caged and bounced back
    to the lobby (**launch issue #13**). Roblox was filling servers during their 30-second
    post-game showcase.
  - The 3-minute join lock "just getting ignored".
  - Randoms freely eating the seats reserved for friends.
  - The match player cap not being respected.

  Bounty now calls `ReserveServer` explicitly and teleports by access code. The **directory side
  was already correct** and was not the bug — every branch of it refuses a closing match, and
  it should not be "fixed".
- **The post-game cage is gone.** A player who somehow still arrives after the buzzer is sent
  straight back to the lobby instead of being frozen at the jail spawn for the rest of the
  showcase. This is now a backstop on a path that should be unreachable, not the fix. It is
  gated on an arrival flag rather than on the round phase, because the winners' characters are
  deliberately reloaded at the buzzer and phase-gating would have ejected them mid-podium.
- **App-side "Join friend" keeps working.** `GetPlayerPlaceInstanceAsync` answers with a jobId,
  which is neither what the directory is keyed on nor what a reserved teleport uses, so Redwater
  now publishes all three identifiers and the lobby maps between them. Without this the whole
  flow would have failed with "your friend's match has already ended", which would have been a
  lie.
- **A party of friends joining a live match goes out as one call again.** The per-member fan-out
  existed only because `ServerInstanceId` is rejected — undocumented — by a multi-player
  teleport. Access codes carry no such limit, so the window in which the target match could fill
  or die *between* members is gone rather than merely narrowed.
- **Abilities are dead during the match summary.** Fortuna could throw cards, Recall, Surge and
  ultimate for the whole post-game showcase, and Dust could still fire High Noon (**launch issue
  #8**). Movement was never the bug — players are already anchored and speed-zeroed for the
  showcase — so only abilities were open. `RoundActive` clears at the buzzer and five of the seven
  server ability modules already read it; Fortuna's `CardsServer` and Dust's `HighNoonModule` were
  the two that never grew that check, and `CardsClient` never read it anywhere either, so Fortuna
  additionally played the entire local cast — animation, card FX, cooldown — against a server
  dropping the request in silence. The round phase now lives in the shared `HunterActionLock`
  predicate instead of a check each hunter has to remember, so all twelve gates inherit it, bots
  included. Redwater only; `HunterActionLock` is **not** one of the 16 mirrored modules (Bounty
  has no `Hunters` folder), so there is no mirror to verify.

## Changed

- **Matchmaking now seats solo players and parties differently.** A lone player may take an
  eighth seat that a party may not. Parties are what *create* half-full matches: one turned away
  starts a new one, and a denied party still has a fine game with 2-4 real humans. A denied solo
  gets one human and four bots — the worst game the mode produces — so the extra seat goes to
  the player who has nothing without it. Friend joins are unaffected and still ignore both
  ceilings.
- **Join lock 3 minutes → 90 seconds.** Retuned in the same release *because* enforcement is
  what changed, not the number. At 180 the rule was aspirational and Roblox overrode it; made
  real, it would have closed over half of every server's life and sent a large share of Play
  presses to fresh solo servers. 90 takes the joinable share of a server's life from 46% to 69%
  while still leaving a joined match worth playing.
- **Friend slots 3 → 2**, with the total unchanged at 10. They sit on top of the solo ceiling
  rather than the party one, so a friend *pair* can still join a full-looking match. The old
  arithmetic reached the same 10 by two mistakes that cancelled.
- Roblox's native **Social Slots** setting is now a no-op — its matchmaker no longer places
  anyone in Redwater, so it has nothing to reserve. No Creator Hub change is needed and Maximum
  Visitor Count stays at 10.

## Internal

- A just-reserved server is advertised on its own behalf until it boots and publishes, so a
  burst of Play presses with nothing open packs into one server instead of reserving one each.
  Under the old blank teleport Roblox did that packing; nothing does now unless the lobby says
  the server exists.
- **A reserved server cannot read its own access code** — there is no API for it. The code
  round-trips through a MemoryStore map and the arriving party's teleport data, with two
  independent sources on purpose: a server that misses both is an orphan, full of players,
  advertised, and unjoinable for its whole life. It warns loudly if it ever happens.
- **There is no blank-teleport fallback left anywhere.** An unreadable directory reserves a
  fresh server instead. Fragmenting is acceptable; failing closed is not.
- Two **safety valves** are in, marked for deletion once verified live: if a multi-player
  teleport rejects an access code, both the Play button and the friend-join path fall back to
  the old per-member dispatch and say so loudly rather than swallowing it. That assumption is
  the one thing here that cannot be tested from Studio, and this API surface has already lied
  once, silently, for days. Every retry inside a valve is pinned to the same server so a
  straggler can only ever land with their party, or nowhere.
- Retired with the fan-out: `partyDestinations`/`sent` bookkeeping, the `forceDestination`
  latch, the `forceBlank` ladder, and the partial-dispatch split risk they existed to manage.
