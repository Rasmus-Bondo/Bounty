## Added

- **A JUMP button on mobile.** Roblox's built-in touch jump button is a fixed size in a fixed
  corner and cannot be restyled or moved, so it could never sit with the rest of the touch
  controls. It is now suppressed and replaced by our own, in the bottom-right cluster under FIRE.
  The press routes through `ManuelJumpClient`'s existing `canJump()` gate rather than setting
  `Humanoid.Jump` — wiring it directly would punch through every ability lock in the game
  (Bram's breach charge, the post-dash clamp, stuns, the victory freeze). Built once at the
  StarterPlayerScripts root because jump is hunter-agnostic, not four times per hunter.

- **A RELOAD button on mobile.** Touch players previously had no manual reload at all: auto-reload
  covers running dry and R covers PC, which left no way to top up a part-full cylinder before a
  fight. Wired into all four hunters. It carries no reload logic of its own — each combat client's
  existing `startReload()` keeps its gating (mid-ability, mid-dash, already reloading, already
  full).
  - Both new buttons are registered with `RoundClientController`'s mobile restore list, so they
    come back when gameplay resumes after intermission. Without it the round HUD manager snapshots
    their authored hidden state and re-hides them for the whole match — the failure the Vesper
    scope button already hit once.

- **`HunterMobileClusterLayout`** (Redwater `Hunters.Shared`) — resolves the position of all five
  touch buttons on both axes at runtime. This cannot be authored: the buttons are sized as a
  fraction of screen *height*, but a `UDim2`'s X can only reference *width*, so authored X scales
  and height-derived diameters drift apart as the aspect ratio changes and the cluster shears.
  Spacing is now expressed in multiples of the jump button's rendered diameter, which also keeps
  the group together on tablets where every button hits its size ceiling.

- **Bots can now be scripted, for authored sequences like an onboarding tutorial.** Nothing here
  changes an ordinary match: every lever is opt-in, defaults off, and was verified inert at
  preflight (`BotDifficulty = Normal`, `HoldFire = false`, `StandDown = false`, live
  `GetDifficulty()` resolving to a `1` damage multiplier). Two peaceful states of increasing
  strength — **hold fire**, where a bot still walks, chases, takes damage and builds ultimate but
  never shoots or uses an ability, and **stand down**, where it holds exactly where it spawned as a
  live damageable dummy. The pair exists because a tutorial needs both: a motionless target while
  the instructions are on screen, and a moving one later or the player never learns to lead a
  shot. Alongside them, a set of controls for placing and steering a bot — spawn one as a named
  hunter at an authored spot, confine it to a radius, walk it along a route dropped into the
  workspace as parts, send it to a player and have it stay with them, give it its own difficulty,
  or remove it outright with no kill or death recorded.
  - Both peaceful flags live on the bot's **record**, not only on its rig, because a respawn clones
    a brand-new character — a rig-only flag would come back armed the first time the player killed
    it. Every authored lever re-applies on spawn for the same reason.
  - One flag disarms all four hunters, because bot aggression leaves the brain through exactly two
    calls. The veto sits inside the firing routine itself rather than at the call site, so a Dust
    Fan or Fortuna burst already in flight stops shot by shot instead of running to completion.

- **A `Training` difficulty tier for bots, and bot damage scaling to go with it.** The three
  existing tiers only ever changed how *often* a bot lands a shot, never what a landed shot costs —
  and since a player has 100 health while Vesper's headshot is 125 and Bram's near headshot is 100,
  **even on Easy either of them one-shots a full-health player**, which no amount of aim error
  changes. `Training` scales bot damage to 0.35 so nothing in the roster kills in under three hits.
  It applies to every damage path including abilities and ultimates — a bot that cannot kill you
  with its gun but still slams you for full has not been made gentler — and Dust's High Noon needed
  it especially, since that ultimate passes a percentage of the victim's max health as a true
  execute that would otherwise ignore every other lever. `Easy`/`Normal`/`Hard` all scale by `1`,
  so this is a no-op outside the tutorial. Difficulty is also per-bot now, resolved when the bot
  spawns, because a tutorial needs two tiers alive in the same round.

## Changed

- **Documentation only, no gameplay effect:** swept both Obsidian vaults to stop `Required by:`
  lists inventing backwards dependencies in the knowledge graphs. A `Required by:` wikilink points
  the edge dependency → dependent, the reverse of what the code does, so the graph was asserting
  things like `laserBeamEffect → FPSRevolverClient` and `TitleRenderer → HealthBarController`.
  569 such links across 195 files are now plain text; the dependent's own file supplies the correct
  edge. 46 real `require()`s that had only ever been recorded backwards were added as forward links
  in 20 files, each verified against live Studio source first, and 19 stale claims that named a
  `require()` no longer present in code were dropped. Both graphs rebuilt.

- **Documentation only, no gameplay effect:** second vault sweep, this time for wikilinks written
  in *prose* rather than in the Dependencies/Connections sections. Those become real graph edges
  too — the update scripts extract links from the whole file — so a sentence naming a script to
  explain a convention it copies, a contrast, or another script's behaviour was inventing a
  dependency. Every prose link whose target was not also declared in the structured sections was
  checked against live Studio source: of 284 such pairs, exactly **two** named a real `require()`
  (`HealthBarSpawnerClient` → `HealthBarController`, `HuntersBuyController` → `WeaponDisplayConfig`),
  and both were missing from their file's `Requires:` line — they are now recorded there properly.
  The other 383 links across 123 files are plain text. The rest were consumer lists, "mirrors X"
  comparisons, and doc headers; `HunterImplementationGuide`, which requires nothing and never runs,
  had been contributing 12 edges on its own. Prose links that merely repeat a dependency the file
  already declares structurally were left alone — they assert nothing false. Both graphs rebuilt;
  Redwater 883 → 676 extracted edges, and the title modules now point renderer → config instead of
  the reverse.

- **Documentation only, no gameplay effect:** restored 7 forward edges Redwater's graph was missing
  because the dependency was written as plain text on the `Requires:` line — the one field the
  builder reads for the forward edge. `BotCombat` was missing all five hunter config modules it
  requires (`CardsConfig`, `GrudgekeeperConfig`, `HighNoonServerConfig`, `RevolverServerConfig`,
  `VesperConfig`), plus `BotController` → `VesperConfig` and `FPSRevolverClient` → `RevolverConfig`.
  Each verified as a real `require()` in live source first. Redwater 676 → 683 extracted edges.
  The `chrono` external library has the same gap in 8 internal links and was deliberately left —
  it is vendored third-party code and its internals are not worth a graph cluster.
  Both CLAUDE.md template fields that caused these two debt classes are now explicit: `Requires:`
  says each module must be a wikilink, `Required by:` says never to use one.
  - `BotCombat` → Bram's `Manifest` added as an 8th link (684 extracted edges), which surfaced a
    separate builder limitation now logged in `OPEN-ITEMS.md`: node ids are the lowercased **file
    basename**, so the four hunters' `Manifest.md` files collapse into one node, as do the two
    `Config.md` and two `Replicate.md`. See that entry before trusting any `manifest` edge.

- **Mobile touch controls regrouped into a single bottom-right cluster.** SPRINT was on the left
  edge above the movement thumbstick on the reasoning that sprint is a movement verb; FIRE and
  SCOPE were on the right. All five (SCOPE / FIRE / RELOAD / JUMP / SPRINT) now sit together on
  the aiming thumb, packed tight against the corner, with FIRE moved inboard off the screen edge
  and resized. Positions and gaps were read off a live playtest with the buttons dragged into
  place by hand, then converted into the layout module's units. **PC is untouched throughout** —
  every change here is on the touch HUD and the touch-only button GUIs.

- **Mobile ammo readout moved above the health bar.** The weapon icon is gone and the ammo count
  and bullet pips now sit side by side over the health bar, tightened so a full six-round cylinder
  (Dust) stays within the bar's width on every screen.

- **Internal cleanup, no gameplay effect: deleted the mobile fire button's dead position solver.**
  Until the cluster rebuild, FIRE hugged the right screen edge and re-derived its own horizontal
  inset against the live HUD. The rebuild gave it a static inboard slot and moved that negotiation
  to the HUD's ability row, which left the old path **unreachable** — `:Start()` had already
  stopped calling it, so it hooked nothing and wrote nothing, and the "two writers racing for
  FIRE's X" risk it was flagged for could not actually occur. Removed with its helpers, its three
  constants and the module's only `require`: 436 → 322 lines. Its per-aspect measurement table is
  kept as a source comment, because it is the record of why a static right-edge offset cannot work
  and is the first thing a future pass would otherwise re-derive the hard way.
  - Two items raised beside it turned out **not** to be defects, and both are written up in
    `OPEN-ITEMS.md` rather than deleted, since each looks real on paper. The ability intro tags'
    three-line reserve is not recoverable screen space — nothing measures that box, both consumers
    measure `TextBounds`, and the longest phrase already wraps to two lines at the ceiling text
    size, so shrinking it would only cost clip protection. And the PC HUD's reported portrait
    overhang was the *mobile* frame's half-width applied to the PC frame, which sits on a
    differently proportioned canvas; measured by rendering both, the PC portrait is 21px **inside**
    the canvas edge. **No PC change was made** — the touch-only scope of this release holds.

- **The mobile RELOAD and JUMP buttons now carry icons instead of "RLD" and "JUMP" text.** They were
  the last two placeholders in the touch cluster — FIRE, SPRINT and SCOPE already had glyphs — so the
  group now reads as one set at a glance rather than three symbols and two abbreviations. Both use
  the same authored recipe as the existing three (a centred `Icon` image at 0.58 of the button,
  scaled to fit), and the text inset each button carried for its label was removed along with the
  label: padding shrinks a button's child box, so leaving it would have drawn the new glyph at about
  a third of the intended size. Checked on the smallest supported phone, a large phone and a tablet.
  - The runtime fallback builders still draw text if the authored button fails to clone on join.
    That path is unreachable in practice and FIRE's fallback is text-only for the same reason —
    icons are authored instances in this project, never script-built.

## Fixed

- **The SWAP HUNTER button no longer vanishes mid-kill-cam, or fails to appear at all when you
  die.** Two separate mobile reports, one root cause: whether the button was up got decided at a
  handful of one-off moments and was never re-checked, so a single check that landed on a stale
  answer stuck for the rest of that life. Because the only thing on the player's side that could
  force another check was pressing the button, anyone who lost that check had lost the control that
  would have asked again — the swap window was simply gone until they respawned.
  - **The vanish.** Every tap that opens the panel asks the server for fresh state, and the reply
    carries the server's view of the player as of when it handled the request. A tap late in the
    kill cam gets handled after the respawn timer has already rebuilt the character, so it answers
    "not down" — and a small network message routinely overtakes a whole character model, so that
    answer arrived before the client knew it had respawned and pulled the button while the player
    was still watching the kill cam. Tapping fast turned a narrow window into a reliable one. A
    pushed state may now only ever *raise* the down flag; the respawn is the only thing that lowers
    it, which is what the two-authority rule this UI is built on already said everywhere else.
  - **The no-show.** The death signal and the replicated health value arrive on independent
    channels, so both existing checks could run while the humanoid still read as alive, and both
    declined. Two more lines of defence now: a per-character health listener that re-tests on the
    write itself, so the button comes up the instant the zero actually lands; and a bounded
    0.2s recheck loop that runs only while the server says the player is down and the button is not
    up, standing down as soon as it appears, the player respawns, or the round ends.
  - Confirmed in a mobile playtest. The existing "down push arrived while local humanoid still
    alive" warning is deliberately kept — it is the diagnostic that says whether the race is still
    firing in the wild and how often, not an error.

- **The touch buttons no longer come apart on tablets.** Every button carries a pixel size ceiling,
  and on a 13in iPad all five hit it — jump wants 192pt and is capped at 135 — while the gaps
  between them kept growing with screen height. Measured there, every vertical gap was inflated by
  exactly the clamp ratio (1.74x): the 33pt between SCOPE and FIRE became 95pt, and the column
  visibly separated. Both axes are now measured in jump-diameter units, so the cluster shrinks and
  grows as one object whether the ceilings bind or not. A second ceiling on button width also fixed
  a pre-existing overlap between the ultimate icon and the ammo pips on several iPads.

- **The hunter portrait no longer hangs off the left edge of the screen on large tablets.**

- **The ammo pips no longer overlap the ultimate icon or run past the health bar.** Worst on a
  six-round cylinder at narrow aspects, where the pips were touching — and on some phones
  overlapping — the ammo number itself.

- **The ability icons no longer jump sideways during a match.** Two separate causes with the same
  symptom. Picking up a health pack parents a ScreenGui into PlayerGui, which re-triggered the
  layout pass and snapped the row ~54pt left mid-fight: the row had resolved once at spawn, before
  the ability intro tags existed, and nothing re-measured after they landed. And at the start of
  every round the row stepped left again about a second in, timed with the intro text appearing,
  because the HUD is rebuilt from its authored position each spawn and re-derived the answer from
  scratch — twice, since the touch buttons are re-enabled on the same boundary and the row was
  briefly clamping against a screen edge instead. The row now measures the tags' visible text
  rather than their reserved (mostly empty) box, keeps measuring until the layout has held still,
  refuses to move at all when it has nothing valid to clamp against, and seeds a rebuilt HUD with
  the placement the previous round settled on — so the first frame drawn is the final one.

- **Mobile auto-fire no longer refuses shots the gun would land through wooden cover.** Aim assist
  decided line of sight with a plain raycast while every hunter resolves its actual shot through the
  shared penetration rules, so wood, planks and fabric — cover a round crosses for reduced damage —
  read as solid to the lock. Auto-fire was strictly stricter than the weapon: hovering on an enemy
  behind a fence, a wooden building wall or a health pack stand kept the gun silent even though a
  manual shot scored. Sight is now decided by the same rules the bullet obeys, for all four hunters
  at once. Cover the round cannot actually cross (three or more walls, an over-thick part, or any
  non-penetrable material) still blocks the lock, and solid geometry behind the wood still blocks —
  this opens up wallbangs the server already allowed, not shots through walls.
  - Worth watching in a mobile playtest: auto-fire will now fire through wooden walls at reduced
    damage, which is a real behaviour change in how aggressive it feels. The lever if it proves too
    strong is `DamageMultiplierPerLayer` per hunter — Vesper's is already tuned down to 0.35.
  - The cheap raycast still runs first and only escalates when it has genuinely hit penetrable
    cover, so a target in the open costs one ray and no allocation (measured: unchanged at ~2.5µs).
