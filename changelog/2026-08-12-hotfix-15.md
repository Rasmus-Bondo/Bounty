## Added

- **The landing camera kick now has a real home: `StarterPlayerScripts.LandingImpactClient`.**

  The short camera jolt when you land, and on Dust's dash, was never owned by a real script. It was
  produced by two `JumpImpact` LocalScripts sitting inside `StarterGui.HunterGui` — a dead GUI tree
  that `StarterGui` copied into every player's `PlayerGui` with both its ScreenGuis
  `Enabled = false`. The panels never rendered, but the scripts ran, and they were the only source
  of the effect. Deleting that tree would have silently removed it.

  **Feel is unchanged, but the tuning is not a copy.** The two old emitters fired *together* on every
  landing (0.045 over 0.08s, and 0.025 over 0.07s) writing independent random offsets to the same
  camera, so their amplitudes added in quadrature. A single emitter at either old value would read
  noticeably weaker, so the new one runs at `sqrt(0.045² + 0.025²)` = 0.0515. Dust's dash kick, which
  only the first copy had, is preserved and still gated through `HunterGate`.

  It sits at the root of `StarterPlayerScripts` and is ungated: every hunter lands, so it serves all
  viewers and has to survive hunter swaps rather than living in a per-hunter folder. Confirmed in a
  live playtest.

- **`ReplicatedStorage.GroupPerkConfig` — which skins the Outlaw Syndicate grants, declared once and
  readable by the client.** The same fact previously existed as three independent copies: a
  server-only table in `DataService`, a `GroupUnlock` flag in `HuntersBuyController`'s skin table,
  and an inline name comparison in `CollectionClient`. All four surfaces now read this module, so
  adding the next group skin is one edit instead of four that can disagree.

  The Collection menu could reach none of the three, which is the bug fixed below.

## Changed

- **The tutorial now ends with the live-fire fight — the two-minute free-roam window is removed and
  the run is ~2 minutes shorter.**

  The last step is a plain 30-second stopwatch again rather than gated on a bot kill, and the
  closing sequence is one card instead of two (the second named the free-roam duration).

  **Revert risk: no data risk, but do not revert one place alone.** The 250 Cash still pays once per
  account at the end of the lesson, EXIT TRAINING during the card still stamps the same return data,
  and the funnel step and `TutorialRun` aggregate already measured the lesson rather than free roam,
  so the analytics stay comparable. But the card's timing is split across both scripts —
  `TutorialDirector.OUTRO_HOLD` 5.4 against `TutorialClient.OUTRO_HOLD` 9.1 — and the client's must
  stay the larger, or the card either fades before the teleport or hangs past it.

  Verified: playtested by the owner.

- **The tutorial's closing card is sized per device — phone 24 / tablet 44 / PC 30.** It rendered at
  one size on everything. Two things corrected while measuring: the character-width constant
  (0.255 → 0.285 — it was still set for the deleted mixed-case line) and the authored `OutroLabel`
  default text, which still carried the removed free-roam sentence.

  Verified on a simulated phone and tablet; widest plate 57% of viewport against a 62% budget, so
  the line cannot wrap.

- **The tutorial now opens on the Bounty logo card rather than a "WELCOME TO BOUNTY" line, and holds
  it two seconds longer.**

  The authored `TutorialGui.CompletionGui` group — logo, gold rule, and "The tutorial will show you
  the game mechanics" — was already in the place and driven by nothing. It is now what the `Welcome`
  payload shows. `WelcomeLabel` stays as the fallback for a place copy without the card. The frame's
  name is a leftover and means nothing; the outro is still `OutroLabel`.

  **Revert risk: the hold is split across both scripts and the server's must stay the larger.**
  `TutorialClient.WELCOME_HOLD` 2.4 → 4.4 and `TutorialDirector.WELCOME_HOLD` 4 → 6. The server's is
  what gates step 1, and firing while the card is up does not fade it, it cuts it. A full-timeout run
  is 2s longer — 230s against the unchanged 300s ceiling.

  It also needed a touch layout, because the card is authored in viewport fractions: on a 360-tall
  phone that is a 13px line of copy and a logo sitting on top of EXIT TRAINING. The card takes a
  pixel height on touch, its copy box is widened past its own parent so `TextScaled` cannot wrap the
  sentence, and the logo shrinks a quarter on phones only. PC keeps every authored value.

  Verified: both scripts recompile; geometry measured and captured at windowed PC, Galaxy A06,
  iPhone 7, Galaxy Tab A8 and iPad Pro 13in — logo clears the button by 11px on all of them. **Not
  playtested.**

- **Redwater dead-code cleanup ahead of the second map: 303 → 292 scripts, ~3,800 lines and 769
  instances removed.** *(no player-visible change)*

  This is groundwork for Frostbite Claim. Everything below lives inside trees that will be
  byte-mirrored to every future map, so removing it now stops it being copied forever.

  - **`StarterGui.HunterGui`** — 769 instances and 6 running LocalScripts (2,735 lines). Superseded
    by `ReworkedHunterGui`, which every hunter HUD actually clones. All four hunter GUI clients
    *defined* a `getHunterGuiTemplate()` that read it, but **none of them ever called it** — the only
    caller was a disabled script — and its other branch pointed at a `ReplicatedStorage.GuiTemplates`
    folder that does not exist. Both were removed with it.
  - **Five disabled LocalScripts** — `FortunaCardsClient` (502 lines, superseded by
    `Fortuna.CardsClient`), `CombatTextClient` (267), `BountyClient` (84), `Fortuna.CardsClientDebug`
    (70), `LocalHealthBarHide` (24).
  - **`ServerScriptService.Testing.BotSpawner2`** and its now-empty folder. Not required by `Main` or
    anything else, and it needed `workspace.BotSpawnerN` parts of which Redwater has zero, so it
    could not have run.
  - **`SpawnService.clearCorpses()`** and its `corpseFolder` lookup — the function was never called
    from anywhere and nothing ever parented a corpse into the folder.

  **The one behaviour that was real got kept**, not deleted — see the landing camera kick above.
  Two comments naming deleted scripts were rewritten, including one in `AimAssistController`, which
  is in a synced tree and would have carried a dangling reference into the new map.

- **Unlocking a group-perk skin now happens where the player is standing, and both buttons read
  `JOIN GROUP TO UNLOCK`.** The Collection used to hand the player off to the Trading Post card, so
  claiming a free skin meant leaving the wardrobe and pressing a second button.

  `Shop.skinUnlock` returns an `action` for the one row that is not a navigation, and
  `Shop.activateSkinUnlock` is the click half. **Callers must not call `Shop.navigate` directly any
  more** — a group perk has no destination, so a caller that ignores `action` navigates nowhere.

  `TextWrapped` is now false on both button labels. At 20 characters the string can otherwise break
  to two lines inside a 22–29px pill and render at roughly half size; one-line fit at full height was
  measured on both (62% and 91% of button width, and both boxes scale with the viewport).

  Verified: owner playtest.

- **The join lock is off — a match in the last stretch of a fight now accepts new players.**
  Redwater's `Config.JOIN_LOCK_SECONDS` 90 → 0; Bounty's `MatchmakingService` only applies the time
  rule when the entry publishes a lock above 0.

  The lock dates from when a server died at the buzzer. Servers loop rounds now, so a player landing
  with 20 seconds left plays those 20 and then a full round — where the old behaviour reserved them a
  fresh server and a game of 1 human + 4 bots. At 90 it closed ~23% of a server's cycle, and the
  lobby's re-check against the entry's age (up to 25s stale) stretched that to ~30%.

  **Revert risk: this is a cross-place contract, publish both or neither.** The number rides on the
  directory entry, so re-enabling the lock is one edit in Redwater's `Config` — but a lobby on the
  new code reading an *old* Redwater server's `open = false` still refuses it, and the lock stays in
  force for every server on the old build until it empties out.

  Both modules recompile. **Not verified beyond that** — routing needs MemoryStore and 2+ live
  servers, neither of which exists in Studio.

## Fixed

- **EXIT TRAINING and the tutorial's intro card were drawing over ordinary Redwater matches.**
  `StarterGui.TutorialGui` had been left `Enabled = true` while the card was being authored. That
  ScreenGui ships in every Redwater server — the lesson and a real match are the same place — and
  only `TutorialClient`, past its `TutorialMode` gate, may turn it on.

  **Reverting is one authored property.** Worth knowing: `RoundClientController`'s round sweep cannot
  catch this, because `TutorialGui` is deliberately in its `SWEEP_EXEMPT_GUI_NAMES` — both halves of
  that sweep get it wrong, and the note there says why.

  Verified: authored state confirmed `Enabled = false` with the card hidden, and boot re-hides the
  card rather than trusting what the Explorer holds.

- **Fortuna's first-person arms were unresolvable — she would have spawned with no arms and no
  cards, and neither card skin would have loaded.** Her viewmodel model had been moved one level up,
  out of `Hunters.Fortuna.Viewmodel.CardsDefaultViewmodel` to `Hunters.Fortuna.Viewmodel`, so the
  path her manifest names resolved to nothing. `HunterClientRuntime` waits 10s on it and then hands
  `CardsClient` a nil template; `WorldAnimationPrewarmClient` was the only thing that said so out
  loud, and it warns for every hunter regardless of who you are playing, which is how this surfaced
  from a session on someone else.

  **This is an instance move, not a script change** — nothing in the 292 scripts referenced the
  location it had drifted to. Moving it back out re-breaks her. `Skins` is a sibling of the template
  by convention (both `CardsClient` and the prewarm read `template.Parent.Skins`), so the container
  is also what makes `PrestigeCard` and `FrozenHand` reachable.

  Verified: the manifest's segments now resolve to the model and to the `Skins` folder beside it.
  Not yet playtested.

- **Fortuna's new smooth arm meshes ignored every visibility rule the blocky arms follow.** The left
  one hung on screen permanently — it should be hidden except during the ultimate cast and the
  reload fade — and the right one stayed fully solid through the ultimate's invisible window while
  the arm it is welded to faded to 0.55.

  Each arm is now treated as a pair in `CardsClient`, resolved by name at viewmodel build and given
  one shared transparency. **Reverting brings back a floating left arm**; the right-arm half only
  shows during the ultimate.

  Verified: recompiled, and the resolver returns the mesh (not the same-named Motor6D) on all three
  templates — `ArmsViewModel`, `PrestigeCard`, `FrozenHand`. The visual itself is **not** playtested.

- **Dust could be left permanently unable to shoot after a Bram Breach Charge**, with rounds still
  in the cylinder — only a reload, dash, High Noon or death recovered it. Reported from the
  tutorial as "couldn't shoot for 5-6 seconds"; ~3.5s of that was the carry plus `SlamStunDuration`
  working as designed, the rest was unbounded.

  Dust's `canShoot` latch is gone, replaced by a `lastFireTime` timestamp checked at click time —
  the shape the other three hunters already used, which is why only Dust had this. Both
  `OnSetCanShoot` callbacks removed with it. Reasoning is in the `FPSRevolverClient` comments.

  **Reverting this restores the bug**, and mobile auto-fire went through the same latch.

  Verified: playtested by the owner for regressions — normal firing and reloading, no warnings or
  errors. The pin path itself was **not** reproduced (staging a bot slam on demand is impractical),
  so the fix rests on the recompile and the reasoning above, not on a repro of the original fault.

- **A reload lost to a pin or stun is no longer lost for good — all four hunters.**
  `HunterAutoReload` fires on the ammo N→0 edge and used to drop the trigger outright if the action
  lock was up at that instant, leaving the player empty with no reload pending. It now holds and
  retries until reloading is allowed.

  Worst for Fortuna — the other three reload from a click on an empty gun, she has no such fallback.
  `RetryInterval = 0` restores the old behaviour if this misbehaves.

  Verified: harness-tested against a live 3.5s block (reloads 0.17s after the lock lifts; no
  double-reload, no leaked loop), plus an owner playtest confirming ordinary reloading is unchanged
  and error-free. The pin path was **not** reproduced in-game.

- **The Trading Post's group-join button did nothing in the live client.** It called
  `GuiService:OpenBrowserWindow`, which is RobloxScriptSecurity, inside a `pcall` that swallowed the
  rejection — so the button looked wired and silently never fired. It now uses
  `GroupService:PromptJoinAsync`, which is unprivileged and joins the group in-experience.

  **Reverting restores a dead button.** Worth knowing for the next one of these: edit-mode testing
  cannot catch this class of fault, because plugin code runs at PluginSecurity and the call resolves
  there exactly as it fails in a shipped client.

  Verified: owner playtest after the change.

- **The Collection offered `PURCHASE` on Dust's Wraith, which cannot be bought at any price in any
  currency.** It is a group perk, and the wardrobe had no way to know — the list was server-side
  until `GroupPerkConfig` (above). The button now reads `JOIN GROUP TO UNLOCK`, the same rule that
  already gave Bounty Pass skins `VIEW IN BOUNTY PASS`.

  Verified: owner playtest.

- **A failed group-membership check is no longer silent.** `grantGroupSkins` returned without a word
  when its `pcall` on `IsInGroup` failed, which is indistinguishable from "not a member" — a genuine
  member saw the skin locked for the whole session with nothing in the log. It now `warn`s. Behaviour
  is otherwise unchanged: still non-fatal, still retried on the next join.

- **The Collection's EQUIP button rendered its label at a fixed 14px on every device**, which on PC
  is a 14px word inside a 533px-wide button. It was the panel's only fixed-size visible label:
  `TextScaled = false`, while PREVIEW directly beneath it — identical in font, weight, colour,
  alignment, wrapping and box size — was already `true`. EQUIP now matches it.

  Checked against every string the button can show, since the text is swapped per tab and a longer
  word renders smaller under `TextScaled`: `USE` through `JOIN GROUP TO UNLOCK` all render at the
  same 52px height at 1080p, the widest being 248px inside a 533px button. Nothing wraps or shrinks
  at the extremes, so no `UITextSizeConstraint` was added — a cap would strand the text on large
  monitors, which is the failure mode the style guide's §3.3 warns about.

  **This is an authored instance property, not script** —
  `StarterGui.CollectionGui.CanvasRight.Background.EquipButton.TextButton.TextScaled`. Reverting is
  setting it back to `false`. Nothing reads or writes it at runtime; `EquipButton.refresh` assigns
  only `.Text`.

  Verified: screenshot at 1080p, and `TextBounds` measured equal on both buttons.
