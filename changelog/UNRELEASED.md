## Added

- **New Bounty - Lobby (place 90720424663491): party pads that teleport a party into Secret.** `PartyPadService` drives the six `Workspace.PartySystemPart` pads: occupancy by root footprint (the `TouchSystem` trigger sits under the disc top, so `Touched` is unreliable), cap 4, rules open / friends-only / closed set by the first occupant, per-player Ready, 5s countdown only when everyone is ready, 30s unready eject, colour and label per state, then `ReserveServer` + `TeleportAsync` to Secret with `TeleportData {source, partySize}`. Client: `StarterGui.PartyPadGui` + `PartyPadClient`, remotes in `ReplicatedStorage.PartyPad` (`SetRule`, `SetReady`, `Leave`, `PadState`). Secret's place id (115630099004249) is a constant in the script because Secret is not in `GameEnvironment` (board #66, deferred). Rollback: delete the script, GUI and folder; players then cannot reach Secret. **Verified live by the owner:** the teleport from lobby to Secret worked. **Not verified:** friends-only, idle eject, the full panel on a phone.
- **Secret to lobby return (board #62).** `ServerStorage.Missions.LobbyReturn` / `LobbyReturnConfig` (lobby id 90720424663491, one home) teleport one player at a time with a pending guard and up to 3 retries; `MissionServer.finishBoardedPlayer` calls it after the one-time reward grant, and a new `ReplicatedStorage.PVE.ReturnToLobby` remote lets players idle at camp leave (refused for active runners). **Not verified:** the teleport itself (Studio cannot), retry path.
- **Local coin drops (board #60).** `CoinDropConfig`, `CoinLedger` (server ledger, `awardScrap` is the single plug point; credits `PVEUnsecured`), `CoinDropServer` (watches `PVE_Enemies`), `CoinDropClient` (pooled parts, one Heartbeat loop, magnet inside 14 studs, no `Touched`), remote `PVE.Remotes.CoinDrop`, mesh at `ReplicatedStorage.PVE.CoinAssets.Coin`. Every eligible player within 150 studs of a kill gets a full drop (total scrap grows with party size); per-archetype values are placeholders. Edit-mode ledger test passed (duplicates, distance, downed, bad ids all paid 0); **not playtested**.
- **Hold ALT frees the cursor, both new places.** Secret: `CombatClient` ALT is now hold (was toggle) and drives `StarterGui.AltCursorGui.ModalButton`; lobby: `AltCursorGui` + `AltCursorClient`. A 1x1 Modal button toggled by `Visible` is what frees the first-person lock; `MouseBehavior` writes lose to the camera.
- **Secret and Bounty - Lobby now persist scrap and camp upgrade levels in the shared `PlayerData_v2` profile.** New `ServerScriptService.PlayerServices.PVEDataService` (identical in both) plus a verbatim `ProfileService` copy; same universe as the main game, key `Player_<UserId>`. It seeds `PVEScrap` / `PVERevolverLevel` / `PVEShotgunLevel` / `PVEGritLevel` from `Data.PVE` on join and mirrors later attribute changes back, so `MissionServer` / `ProgressionServer` are untouched; loose salvage (`PVEUnsecured`) is deliberately not saved. `DataService` templates in Bounty, Redwater and Frostbite gained the same `PVE` block (Reconcile-safe, no `DATA_VERSION` bump). `ProgressionServer` re-applies Grit max health when the loaded level arrives after first spawn. Rollback: delete `PVEDataService`; saved `Data.PVE` stays in profiles unused. **Not playtested** (compile-checked only): needs a throwaway-account earn, leave, rejoin, and a lobby to Secret round trip; Studio writes the live store.
- **Lobby party pads pick the mission; Secret starts it directly (#48).** The pad owner steps a mission row (Easy / Mine / Escort / TNT / Valves / Hard) in `PartyPadGui` (new `MissionHeading` + `MissionRow`, lower rows re-spaced); changing it clears every ready. The token rides `TeleportData.mission`, and Secret's `MissionServer` starts that job without the camp vote or camp-distance check, and `MissionClient` hides the vote panel and job board on day 1 (they open only after Continue on the train). An unknown token falls back to the board. `MissionClient` gains a LEAVE TO LOBBY button (Idle only) wired to the existing `ReturnToLobby` remote. Revert risk: none to stored data; reverting only one place leaves a token Secret ignores or a button the lobby never fills. Not verified in a live server: compiled and screenshot-checked at four viewports only, so it owes a two-place playtest (Testing on #48).

## Changed

- **Secret (PVE place) reorganised into domain folders, no behaviour change.** Scripts moved out of the flat `PVE*` lists into `Combat/ Enemies/ Missions/ World/ Mounts/ Progression/` (server and client; client also `Player/`), `PVE` prefix dropped, `PVEEncounterServer`/`PVEEncounterClient` renamed `MissionServer`/`MissionClient` (`NearbyMission`, `MissionDiscovery` likewise). ReplicatedStorage.PVE modules regrouped into `Config/` (`Config` renamed `CombatConfig`) and `Modules/`; `chrono` moved to `PVE/Packages`. ServerStorage modules grouped into `Missions/ Nuclear/ World/`; 113 `Before*`/`Secret_Before*` snapshots and the unused `Jumping Coin Collect` moved to `ServerStorage._Archive`. Runtime names (`PVE_*` workspace folders, `PVE*` Bindables, ScreenGui and attribute names) deliberately unchanged. Rollback: requires were rewritten by hand, so reverting means moving scripts back AND restoring the `require` lines. **Verified:** all 129 live scripts compile and no live script references an old path; **not playtested** (no MCP playtesting). Secret is outside the three-place publish set. New vault `LocalSecret/` and graph `graphs/SecretGraph/` (`update_secret_graph.py`).
- **Job board only opens the panel; a job starts from the first click on a card.** `startPrompt.Triggered` no longer starts a run (`startFromVote` does, from the vote remote, while the phase is Idle), the first click counts as that player's vote, and there is no vote timer: the most-voted job starts 10s after the first vote. The panel closes by clicking the dark area outside it and reopens with E at the board or J. Rollback needs both `MissionServer` and `MissionClient` reverted together or the board does nothing. **Not playtested.**
- **Workbench works while the job vote is open** (`ProgressionServer.awayFromCamp`, `ProgressionClient`): the vote sets `PVEInEncounter` immediately, which used to lock upgrades for the whole vote. The panel closes when the job really starts.
- **Ignoring the train sends the player to the lobby.** At the end of the 35s Decision window, anyone with no Continue/Extract answer is extracted (a sentinel `departingPlayers[p]=true` for players too far from the door; `departTrain` now moves only CFrame entries).
- **A lost expedition sends everyone still in it to the lobby, 6s after the failure.** New `participants` set (the roster drops the dead long before a wipe) and `cleanupRun(result, skipLobby)`; `Failed` and `TravelFailed` both send, the crash-recovery path passes `skipLobby`. Every timeout (travel, return, secure reward) ends as one of those.
- **Trail boon panel closes by clicking outside and reopens with B** (`RunBoonClient`); an unclaimed boon still defaults to Gunsmoke.
- **Secret menus free the cursor on PC.** Dedicated modal button driven by `CombatClient`'s menu check, plus `MenuModalGuard` marking buttons inside menu panels only (never the always-visible trail map `MapButton`: that kept the cursor free for good and broke shooting once), and `PromptClickGuard` turning off `ClickablePrompt` for keyboard players.
